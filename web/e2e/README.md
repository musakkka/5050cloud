# web/e2e

The console's Playwright suite (docs/SPEC.md 13.8). It drives only the UI of a
real install and reads state through the API for assertions.

```sh
cd web/e2e && npm ci
E2E_CONSOLE_URL=https://console.example.com E2E_SETUP_TOKEN=XXXX-XXXX npx playwright test
# against a local dev control plane and `npm run dev` in web/:
E2E_CONSOLE_URL=http://127.0.0.1:5173 E2E_BROWSER_CHANNEL=chrome npx playwright test
```

| Path | What |
|---|---|
| `playwright.config.ts` | Projects: `setup` (U1, saves the owner session to `report/owner.json`), `desktop`, `mobile` (375 px, `*.mobile.e2e.ts`) |
| `harness/` | `env.ts` (environment variables), `api.ts` (read-only API helpers, `until`), `ui.ts` (new project, + Create, Deploy), `totp.ts` (RFC 6238 codes for 2FA steps) |
| `specs/shell/` | WP8a: U1 (setup and login), U3, U14 (shell part), U26, U27 (shell part), labels, perf P1 and P4 |
| `specs/<feature>/` | Owned by the package that owns the screen (WP8b, WP8c) |
| `labels.json` | Generated by `make labels` from SPEC section 2. Do not edit |

Spec files end in `.e2e.ts` so the console's Vitest run never collects them.
`labels.e2e.ts` maps each labels.json row to the screen that shows it in
`SCREENS`; unmapped rows are skipped with a note, so a package adds its rows
there when its screens land.
